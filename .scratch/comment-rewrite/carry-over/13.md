## `reportFailures`

- **Where:** `src/cli/commands.ts:287`.
- **The old comment:** "Without this a failure reads as a summary row with no cost against it and no reason given — the message is in the manifest and the run log, but the user should not have to open either to learn what went wrong (technical-design.md §8)."
- **Checked against the code:** yes. The failed stage's message is in the stage entry (`entry.error`), and the run summary gives no message. technical-design.md §8, "Stage Failure Protocol", item 5, says that the CLI names each failed stage and its message. It gives a different reason: the two audiences need different things.
- **Where it belongs:** technical-design.md §8, "Stage Failure Protocol".
