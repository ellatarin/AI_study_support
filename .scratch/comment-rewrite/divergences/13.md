# Divergences found in ticket 13

A line number in `src/` refers to the code at commit `fb437d0d`, the commit before this ticket.

## D13-1 — The CLI writes no blank line between two cost reports

- **Where:** `src/cli/commands.ts:418` (`reportCosts`), found in ticket 13.
- **The code does:** `reportCosts` writes each report as `` `${report}\n` `` (line 437). `formatCostReport` (`src/pipeline/reports.ts:497–511`) joins its lines with `"\n"`, and its last line is a line of the experiment section, not an empty line. So the next report starts on the line after the last line of the one before. A run summary gets `\n\n` (`commands.ts:269`), so it does get a blank line.
- **The intent says:** the old comment. It says this.
  > "one rendered report per lecture, each followed by a blank line as every other block of CLI output is"
- **Other sources:** none.
- **Status:** open

## D13-2 — `openLecture` throws named manifest errors, not the filesystem error

- **Where:** `src/cli/lecture-identity.ts:41` (`openLecture`), found in ticket 13.
- **The code does:** `openLecture` calls `readManifest` (`src/pipeline/manifest.ts:92–125`). `readManifest` throws `ManifestUnreadableError`, `ManifestNotJsonError` or `ManifestShapeError`. It does not pass on the raw filesystem error.
- **The intent says:** the old comment: "@throws Rethrows the filesystem error when the manifest cannot be read."
- **Other sources:** technical-design.md §8, "Typed Errors", agrees with the code. It says this.
  > "a filesystem error or a `SyntaxError` on its way out through one of them is caught and rethrown as the module's own"
- **Status:** open

## D13-4 — The reset count for `run` costs no scan, and the count for `batch` scans only the batch's modules

- **Where:** `src/cli/commands.ts:515` (`confirmReset`), found in ticket 13.
- **The code does:** `runLectures` gives `confirmReset` the count `matches.length` (line 321), with no scan. `batchCommand` gives a count that normalises and then calls `countLectures` on the batch's own modules (lines 380–383). With a named module, that is one module.
- **The intent says:** the old comment. It says this.
  > "The count is taken lazily because establishing it costs a scan of every configured module, which an ordinary run must not pay for."
- **Other sources:** technical-design.md §4.7 agrees with the code. Its paragraph on the reset question says that the question is asked "for a batch, only after `countLectures` has scanned the modules".
- **Status:** open
