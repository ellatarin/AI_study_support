# Divergences found in ticket 12

A line number in `src/` refers to the code at commit `fb437d0d`, the commit before this ticket.

## D12-1 — The technical design gives `accumulateCost` no `null` running total

- **Where:** `src/utils/cost.ts:40` (`accumulateCost`), found in ticket 12.
- **The code does:** `current` is `StageCost | null`. A `null` running total gives back `incoming` unchanged (`cost.ts:47–49`). `totalCost` and `sendUntilAccepted` both start from `null`.
- **The intent says:** technical-design.md §7, "Cost and Reporting Modules" (line 1967): "`accumulateCost(args: { current: StageCost; incoming: StageCost }): StageCost`".
- **Other sources:** the old TSDoc of `accumulateCost` agrees with the code: "The running accumulator, or `null` before the first call."
- **Status:** open

## D12-2 — The JSON files of the pipeline are not all written in one format

- **Where:** `src/utils/files.ts:163` (`writeJsonAtomic`) and `src/utils/files.ts:142` (`jsonFileContent`), found in ticket 12.
- **The code does:** `writeJsonAtomic` writes indented JSON with no newline at the end (`files.ts:170`, and the test at `files.integration.test.ts:49`). It writes the manifest, the run logs and the saved runs of a panel (`panel-runs.ts`, `runPanel`). A stage output and its stage record go through `jsonFileContent`, which adds a newline at the end (`pipeline-stage.ts`, `writeStageOutputWithStageRecord`). So the JSON files of the pipeline have two formats.
- **The intent says:** the old `writeJsonAtomic` comment: "Every JSON file the pipeline persists — the lecture manifest and the run logs — is read by a human before it is read by anything else, so they are all formatted the same way." The old `jsonFileContent` comment: "indented as every JSON file the pipeline writes is". technical-design.md §4.3 (line 492) names only the manifest and the run logs.
- **Other sources:** none. The indentation is the same in both formats. Only the newline at the end differs.
- **Status:** open

## D12-3 — One caller of `readJsonSafe` does not skip a file it cannot read

- **Where:** `src/utils/files.ts:236` (`readJsonSafe`), found in ticket 12.
- **The code does:** `readJsonSafe` has three callers: `readRunLogs` (`runner.ts`), `readManifestSafe` (`manifest.ts`) and `readSavedRun` (`panel-runs.ts`). `readSavedRun` first checks that the file exists. When `readJsonSafe` then gives a value that is not a run, it throws `SavedRunUnreadableError`. It does not skip the file.
- **The intent says:** technical-design.md §4.3 (line 488): "Answers with a value rather than a throw because both callers scan speculatively — the runner over whatever `Run logs/` holds, `readManifestSafe` over a folder that may not be a lecture." The old comment adds: "neither has anything to say about a file it cannot read beyond skipping it".
- **Other sources:** technical-design.md §5, "Dividing the transcript", Panel runs, agrees with the code: "A saved run file that cannot be read is a named error rather than a run to remake".
- **Status:** open

## D12-4 — No caller of `filenameSafe` falls back when the title is empty

- **Where:** `src/utils/naming.ts:26` (`EmptyNameError`) and `src/utils/naming.ts:182` (`filenameSafe`), found in ticket 12.
- **The code does:** `renameLecture` (`src/cli/lecture-identity.ts:73–80`) catches the error and throws `LectureIdentityError`. `deriveBaseName` (`transcript-structuring.ts`) catches it and throws `TranscriptStructuringError`. `orderLectures` (`lecture-resolution.ts`) calls `lectureBaseName` and does not catch it. - **The intent says:** technical-design.md §4.4 (line 543): "Reject an empty result — the caller must fall back to `provisionalTitle` or a stage-defined default." The old comments on `EmptyNameError` and on the `@throws` of `filenameSafe` say the same.
- **Other sources:** none.
- **Status:** open

## D12-5 — The progress bars write to stderr, and the technical design says stdout

- **Where:** `src/utils/progress.ts:19` (`PROGRESS_STREAM`), found in ticket 12.

- **The intent says:** technical-design.md §10, "Output Streams" (line 2161): "| Progress | stdout (cli-progress) | Real-time stage progress bars |".

- **Status:** open

## D12-6 — No caller of `pathExists` asks if a lecture PDF exists

- **Where:** `src/utils/files.ts:43` (`pathExists`), found in ticket 12.
- **The code does:** `pathExists` has three production callers. `recordedFileExists` in `pipeline-stage.ts` asks if a stage output in the manifest is still on disk. `completeInterruptedRenames` in `source-renames.ts` asks if the rename target is taken. `readSavedRun` in `panel-runs.ts` asks if a saved run is there. The other callers are tests. No caller asks if a lecture PDF exists. The first example of the old comment, a stage output, agrees with `recordedFileExists`.
- **The intent says:** the old comment, quoted in full below. Only the lecture-PDF example in it has no caller.

  ```text
  every caller is choosing between two ordinary outcomes — a stage output that still exists or has been deleted, a lecture PDF that has been produced or has not yet.
  ```
- **Other sources:** technical-design.md §4.3 lists "a lecture with no PDF" as an example of a read that may find nothing, without naming `pathExists`.
- **Status:** open
